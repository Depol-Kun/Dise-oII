ESTRUCTURA PROPUESTA - APP WEB EQUIPO DE BASQUET BARRIAL (guia general del nuevo proyecto sin framework)
============================================================================================

ENFOQUE DE DESARROLLO (restricciones tecnicas del proyecto)
-----------------------------------------------------------
- Sin framework (todo en PHP nativo, estructura propia).
- Sin ORM (consultas SQL directas con mysqli/PDO).
- Sin template engine (vistas .php nativas, con includes/parciales).

ARBOL DE CARPETAS (cada elemento con su funcion)
------------------------------------------------
proyecto-basquet/ (carpeta raiz del proyecto)
  public/ (punto de entrada web y archivos publicos)
    index.php (front controller: recibe todas las peticiones)
    assets/ (recursos estaticos visibles por el navegador)
      css/ (hojas de estilo del proyecto)
      js/ (scripts del lado cliente)
      img/ (imagenes y logos del equipo)

  app/ (codigo principal de la aplicacion)
    Core/ (clases base reutilizables)
      App.php (arranque general de la aplicacion)
      Router.php (define y resuelve rutas)
      Controller.php (clase base para controladores)
      View.php (ayudas para renderizar vistas)
      DB.php (conexion y utilidades de base de datos)
      Validator.php (validaciones de formularios)
      Session.php (manejo de sesion y mensajes flash)

    Controllers/ (reciben request, validan y coordinan modelo-vista)
      HomeController.php (pantalla inicial/dashboard)
      JugadoresController.php (CRUD de jugadores)
      ActividadesController.php (CRUD de actividades: entrenos/partidos)
      AsistenciasController.php (CRUD y filtro por actividad de asistencias)
      AuthController.php (login, logout y control de acceso)

    Models/ (consultas SQL y reglas de datos)
      Jugador.php (operaciones de tabla jugadores)
      Actividad.php (operaciones de tabla actividades)
      Asistencia.php (operaciones de tabla asistencias/inscripciones)
      Usuario.php (operaciones de usuarios del sistema)

    Views/ (plantillas HTML/PHP)
      layouts/ (partes compartidas del diseno)
        head.php (etiquetas head, css y metadatos)
        header.php (barra superior/navegacion)
        aside1.php (menu lateral principal)
        aside2.php (panel lateral de acciones)
        footer.php (pie de pagina)
        templateStart.php (inicio del layout comun)
        templateEnd.php (cierre del layout comun)

      home/ (vistas de inicio)
        index.php (pantalla de bienvenida)

      jugadores/ (vistas del modulo jugadores)
        index.php (listado de jugadores)
        _form.php (formulario reutilizable de alta/edicion)
        nuevo.php (pantalla para crear jugador)
        editar.php (pantalla para editar jugador)

      actividades/ (vistas del modulo actividades)
        index.php (listado de actividades)
        _form.php (formulario reutilizable de alta/edicion)
        nuevo.php (pantalla para crear actividad)
        editar.php (pantalla para editar actividad)

      asistencias/ (vistas del modulo asistencias)
        index.php (listado de asistencias, opcionalmente filtrado por actividad)
        _form.php (formulario reutilizable de alta/edicion)
        nuevo.php (pantalla para registrar asistencia/inscripcion)
        editar.php (pantalla para editar asistencia)

      auth/ (vistas de autenticacion)
        login.php (pantalla de inicio de sesion)

  config/ (configuraciones del proyecto)
    app.php (configuracion general: nombre app, zona horaria, etc.)
    database.php (configuracion de conexion a BD)
    routes.php (tabla de rutas y metodos HTTP)

  database/ (scripts SQL)
    schema.sql (estructura de tablas e indices)
    seeds.sql (datos de prueba iniciales)

  storage/ (archivos generados en runtime)
    logs/ (registros de errores y eventos)

  .env (variables sensibles: host, usuario, password)
  README.md (documentacion de uso e instalacion)


MAPEO DE MODULOS (0416 -> NUEVO PROYECTO)
------------------------------------------
- usuario -> jugadores (gestion de personas del equipo)
- eventos -> actividades (entrenamientos, partidos, torneos)
- inscriptos -> asistencias (quien asistio/esta anotado)


METODOS A CONSERVAR (MISMO PATRON 0416)
----------------------------------------
Para cada modulo principal (jugadores, actividades, asistencias):
1) index (aqui listamos registros)
2) nuevo (aqui mostramos formulario para crear)
3) guardar (aqui insertamos en base de datos)
4) editar (aqui editas el jugador/actividad/asistencia)
5) actualizar (aqui se guarda la edicion en base de datos)
6) borrar (aqui eliminamos un registro)

Nota para asistencias (detalle importante del flujo):
- Debe existir listado por actividad_id (muestra solo los de una actividad).
- Debe mantener el flujo contextual (volver a actividades/listado filtrado).


RUTAS SUGERIDAS (con accion que realiza)
----------------------------------------
GET  /jugadores (muestra listado de jugadores)
GET  /jugadores/nuevo (muestra formulario de alta de jugador)
POST /jugadores/guardar (guarda nuevo jugador)
GET  /jugadores/editar?id=ID (muestra formulario para editar jugador)
POST /jugadores/actualizar (actualiza jugador existente)
POST /jugadores/borrar?id=ID (elimina jugador)

GET  /actividades (muestra listado de actividades)
GET  /actividades/nuevo (muestra formulario de alta de actividad)
POST /actividades/guardar (guarda nueva actividad)
GET  /actividades/editar?id=ID (muestra formulario para editar actividad)
POST /actividades/actualizar (actualiza actividad existente)
POST /actividades/borrar?id=ID (elimina actividad)

GET  /asistencias?actividad_id=ID (lista asistencias por actividad)
GET  /asistencias/nuevo?actividad_id=ID (muestra alta de asistencia para esa actividad)
POST /asistencias/guardar (guarda asistencia)
GET  /asistencias/editar?id=ID&actividad_id=ID (muestra edicion de asistencia)
POST /asistencias/actualizar (actualiza asistencia)
POST /asistencias/borrar?id=ID&actividad_id=ID (elimina asistencia)


REGLAS TECNICAS MINIMAS (buenas practicas base)
-----------------------------------------------
- Sin framework, sin ORM y sin template engine (decision fija del proyecto).
- Todo entra por public/index.php (entrada unica para ordenar el flujo).
- Controllers coordinan request/response y validaciones (logica de accion).
- Models concentran consultas SQL manuales (acceso a datos en un solo lugar).
- Views solo muestran HTML/PHP nativo (sin motor de plantillas externo).
- Config y credenciales en .env (evita hardcodear datos sensibles).
- Mensajes de exito/error con session flash (feedback claro al usuario).


PLAN DE MIGRACION (SIMPLE)
--------------------------
1) Crear estructura base (preparar carpetas y archivos nucleares).
2) Pasar parciales/layouts actuales a app/Views/layouts (reutilizar tu diseno).
3) Migrar primero modulo jugadores (base para repetir patron CRUD).
4) Migrar actividades (mismo patron con datos de entrenos/partidos).
5) Migrar asistencias (incluyendo filtro por actividad).
6) Probar CRUD completo por modulo antes de continuar (validar que no se rompa nada).
